# Widget design

Reference: the live widget on https://userjot.com/in-app-feedback-widget, observed 2026-11-09. Use Quills branding and official Phosphor icons; use demo initials instead of UserJot's visitor portraits. These are deliberate brand/content differences, not a claim of pixel identity.

- Desktop panel: 384 × 760 px, 16 px edge inset, 20 px radius, constrained to viewport height. Mobile: full screen at widths up to 760 px. The launcher is a white 40 px circle with a dark messaging icon, 20 px from the edge; it hides while the panel is open.
- Inter, locally served under its included SIL OFL, with UserJot’s cv11/ss01 features, antialiased smoothing, and optimizeLegibility rendering. Base 16 px with normal line height and −0.16 px tracking; message-card title and quick links 15 px/20 px; body copy 13–14 px; screen headings 26 px/1.15, weight 600, tracking −0.624 px; update headings 20 px/1.3. Navigation labels 10.5 px.
- Light surfaces: white panel, #f5f5f5 cards, #fbfaf8 footer, #282624 text, #6c6966 secondary text, #ebebeb rules. Dark surfaces: #1a1a1a panel, #292929 cards, #1f1f1f footer, #f5f5f5 strong text, #d4d4d4 body text, and #a4a09d secondary text. Secondary text is deliberately stronger than the reference for readability. Colors are scoped to `.qb-widget`.
- Header 58 px; five-item navigation 67 px; attribution footer 30 px. Home starts 128 px below the header. Message card radius 18 px; quick links and update cards 16 px; active navigation icon pill 46 × 26 px.
- Fixed navigation stays visible while the content scrolls. Composers use the full content area and hide navigation. Feedback and conversation actions sit above the navigation. Feedback has a native sort selector in the round filter affordance. Updates have reaction counts and a share button backed by supplied actions. Search, back, close, empty states, pending state, error state, and retry are implemented.
- Preserve visible keyboard focus and reduced-motion preferences. Closed host panels are inert. Do not replace supplied content with HTML or add fake production actions. Unavailable submission actions are disabled with an explanation.
- Hover feedback uses the existing neutral surfaces. Focus, selection, caret, scrollbars, and errors use theme tokens. Search has a shared clear control that returns focus to the field; whitespace around queries is ignored. Empty searches show a recovery hint.
- Composers use a labeled, inset writing surface with a linked description and error. Pending fields are read-only, so visitors can still select their draft; submission remains locked. Lists keep their primary action near the bottom even with few items. Preview titles clamp to three lines (two for earlier updates); details retain the complete text.
- Short viewports reduce the home greeting's top space. Touch input has larger controls and 16 px search text. Mobile header, footer, and composer account for device safe areas. Long unbroken content wraps without horizontal overflow.
- Returning Home uses a shorter greeting area and a resume-conversation card. Unread dots come from supplied data; availability is shown only when supplied by the host. Loading uses quiet static placeholders, and connection/error banners keep recovery actions near the content.
- Conversation bubbles group adjacent messages by author and date. Visitor messages use the existing dark neutral surface. The reply composer stays in the scroll flow above navigation. Feedback details use explicit pressed vote/follow controls, including their reverse actions, with the status shown above the title.
- Drafts and filters belong to the mounted visitor session. Back restores list position; looking up an article never destroys a draft. Suggested articles are compact rows below the writing field. Article blocks are text, with restrained heading/list/code styles. Detail entrances use a short fade/translation disabled by reduced motion.

Use Widget / Design in Storybook for visual checks. Widget / SDK separately verifies the actual singleton, React hooks, and iframe protocol against a local fixture. The stylesheet is an explicit optional import and must not enter the vanilla SDK bundle.

Measured against the live reference on 2026-11-09: header padding 14px 16px 12px and gap8px; message card170px; quick links46px with12px gap; navigation padding4px 6px 6px and56px buttons. Feedback search15px/−0.24px, vote pills64×32px, reaction pills32px. Use actual Phosphor regular and fill paths for inactive/active navigation; never fill or stroke an outline path through CSS. The footer is always “Powered by Quills,” independent of the host header brand.

## Screenshot parity, 2026-11-09

The eight supplied UserJot screenshots are the authority for detail composition. At 1×, readers use approximately 480 × 860 px; compact request/composer/roadmap panels use 384 × 760 px. All dimensions remain viewport constrained. Help, full updates, requests, and feedback compose hide tabs and attribution. New conversation hides tabs but retains attribution; roadmap retains both.

Readers use a white surface, 22 px inset, 26 px title, 15 px body, author metadata, and Back/Close. Updates end with reactions and linked requests. Request details use 36 px author avatars, 22 px titles, a status/voters/vote row, a dashed divider, comment composer, and threaded replies. Missing portraits render initials; the demo does not reuse UserJot portraits or invent verified identities.

The message greeting sits near the bottom above a compact white message box. Feedback uses an open writing surface with image/camera tools and Post at the bottom. Roadmap shows grouped status rails and three entries before Show more. Annotation is an additional restrained native dialog; the screenshots do not establish its exact visual design. Keyboard position controls provide an alternative to pointer drawing.

Inter remains intentional for the requested reference match. Official Phosphor 2.1.1 SVG paths remain the icon source. No new broad design-hook suppression is required.

Activity uses compact chronological rows with unread dots and explicit read controls, reached through the header without adding a sixth tab. Article feedback sits after the body with quiet Yes/No pills and a contextual message link. New conversation context is a plain line above the composer. Images use a native modal with themed controls and keyboard-scrollable zoom. A small sticky Jump to latest control appears only while reading away from the conversation bottom. These additions preserve the reference's typography, spacing, neutral palette, and Phosphor icons.
